# 0.6.0rc1 release candidate

This candidate prepares `milestone/v0.6` for separately authorized owner
integration. No merge to `main`, tag, package publication or live deployment is
claimed. Task 24 final review and current root gates are recorded in the
[closeout report](../subagent_execution_plan/v0_6/24_v06_release_closeout-report.md).

## Delivered behavior

The fixed `canonical_founders_v1` preset composes existing managers for water,
food, shelter, storage, work, goals, settlement promotion and homeland dispatch.
Proposal tapes remain untrusted input to ordinary filtered cognition and the
action gateway. Managers own mutations; immutable events explain the outcomes.

From the root of this candidate source checkout, using a Bash shell:

```bash
make install
source .venv/bin/activate
living-world run --founders success --database success.sqlite3
living-world run --founders stall --database stall.sqlite3
living-world run --founders failure --database failure.sqlite3
living-world inspect --founders --database success.sqlite3 --port 8000
```

`make install` installs this checkout into `.venv` with development dependencies,
including uvicorn; activation selects its candidate `living-world` entry point.
This does not require a published package. For a separately supplied wheel, the
optional `server` extra supplies uvicorn; publication remains separate.
Open [the local inspector](http://127.0.0.1:8000/inspector). Saved-world inspection opens an existing SQLite snapshot
read-only, validates canonical setup and serves a fixed in-memory view. GET-only
routes expose privileged engine truth and never feed NPC prompts. A separately
running simulation does not refresh that snapshot automatically.

The accepted outcomes are success at complete tick 10 (`settlement_success`),
stall at tick 5 (`tick_limit`), and failure at tick 13 (`founding_failure`). Fresh
runs and checkpoint/resume at ticks 1, 3 and 4 preserve the complete schema/payload,
including events, IDs, work charges and replay cursor. Terminal success/failure
resumes take zero additional steps. See the [operator guide](../canonical_founders.md)
for partial-run bounds and exact composition timing, [API](../http_inspection_api.md),
[inspector](../world_inspector_ui.md) and [information boundary](../npc_information_boundary.md).

## Known limits

- Tapes demonstrate deterministic unattended execution, not successful live-model
  strategy selection or production security/physical realism.
- This is a fixed preset, not a generic scenario authoring framework. Provision
  is an abstract recipe; population stays two. Town promotion is tested separately.
- Generic stage templates, decline/demotion and automatic NPC stage perception
  remain future work. No new automatic observations or memories are fabricated.
- Off-map references model bounded dispatch, not a simulated remote economy.
- Dense map labels can overlap; the accessible complete placed-record list remains
  the fallback. Inspection is privileged and has no authentication boundary for
  exposure to an untrusted network; use the default loopback binding.

Future milestones and owner integration/tagging require their own authorization.
