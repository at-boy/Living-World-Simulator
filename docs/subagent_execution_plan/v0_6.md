# v0.6 — Autonomous founding settlement

## Objective

The proposed v0.6 milestone is an end-to-end autonomous founding-settlement
vertical slice. A small founding group should be able to establish shelter,
food, storage, and a homeland trade route through engine-owned goals, needs,
work, and settlement-stage criteria while preserving simulation authority and
the NPC information boundary.

The acceptance target is to start one command, run the canonical scenario for
a bounded period without operator intervention, inspect why it succeeded,
stalled, or failed, and replay the same configured seed. The complete scope and
dependency order are in the
[post-v0.5 settlement-evolution roadmap](../post_v05_settlement_evolution_roadmap.md#v06--autonomous-founding-settlement-vertical-slice).

## Branch and task status

The user authorized the v0.6 milestone and its complete planning sequence.
`milestone/v0.6` is the active integration branch. Each isolated implementation
task uses a pushed `task/<task>-<slug>` branch created from the current
milestone branch and returns only after independent review and validation.
The orchestrator may push and merge into `milestone/v0.6`, but must not commit,
merge, or push to `main`.

The [`v0_6/`](v0_6/) directory includes two earlier supporting observability
drafts that must be amended to the approved stack and split boundaries before
their implementation begins:

- [Task 15 — read-only World Inspector UI](v0_6/15_world_inspector_ui.md)
- [Task 15a — spatial world inspection](v0_6/15a_spatial_world_inspection.md)

The milestone authorization permits the documented dependency-ordered tasks to
proceed one at a time after their individual plan and saved prompt exist. Every
task still requires a truthful report, independent review, boundary compliance,
and full validation before it can land.

20a are reviewed, merged, and pushed. Task 20b is next and requires a fresh

12. Task 24: release-readiness closeout on the milestone branch.

Task 24 leaves the milestone branch ready for owner integration. It does not
merge v0.6 into `main`.
